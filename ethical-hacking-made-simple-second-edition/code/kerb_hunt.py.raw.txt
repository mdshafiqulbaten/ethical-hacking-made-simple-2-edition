  Sigma is a widely used, vendor-neutral format for describing a de‐
  tection rule as text so it can be shared and translated into different
  platforms' own query languages. Write Lab 24.2's rule in this plain
  style:

      title: Successful login following multiple failures from the
      same source
      logsource: category=authentication
      detection:
        failures:
          event_type: Failed
        success_after_failures:
          event_type: Accepted
          condition: failures | count() >= 5 by source_ip within 60s,
      followed by success from same source_ip
      level: medium
      false_positives:
        - A user who mistypes a password several times and then
      succeeds

  What good looks like: your version names the condition, the time
  window, the severity level, and at least one realistic false-positive
  scenario, which is what separates a usable detection rule from a
  vague description of "suspicious activity."

Key Takeaways
  Detection logic looks for relationships between events, not single
  events in isolation.
  A rule's threshold and time window are design decisions that
  should be written down and justified.
  The same packet-reading skill from Chapter 4 applies to detec‐
  tion; the difference is asking "is this normal?" instead of "what
  does this mean technically?"
